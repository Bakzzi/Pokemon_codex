# 포켓몬 작은 모험 · Android

터치로 지도 위를 이동하고, 폰을 사용하는 동안 동료들이 모험하는 비공식 비영리 팬 게임입니다. 원작 **모모찡 · momozzing**의 [Digimon_mod](https://github.com/momozzing/Digimon_mod)에서 출발했습니다. 기존 Windows 앱과 별개로 저장됩니다.

이동 자원은 12시간마다 1개씩 쌓이며 직접 사용해 이동할 수 있습니다.

## 설치와 사용

Android 12 이상에서 [Android 배포본](https://github.com/Bakzzi/Pokemon_codex/releases/tag/android-v0.1.104)의 APK를 설치하세요. 첫 실행에는 안내 대사가 자동으로 이어집니다. **도감 · 타운맵 · 가방 · 모험 기록**에서 동료와 진행을 확인하세요.

- **폰 사용 20초당 모험 행동 1회**를 진행합니다. 다른 앱을 이용하는 동안에도 모험이 이어지며, 대화와 선택은 직접 확인합니다.
- 홈이나 설정에서 **터치 기록 켜기**를 눌러 그림 안내를 보세요. **접근성 설정 열기**를 누르고 **포켓몬 작은 모험 · 터치 기록**을 켭니다. 다른 앱의 버튼 누르기, 스크롤, 입력란 변경 횟수를 기기에 저장합니다. 통계는 오늘·이번 달·전체로 표시합니다.
- **앱 액세스가 거부됨**이 뜨면 게임의 터치 기록 안내에서 **앱 정보 열기 → 오른쪽 위 ⋮ → 제한된 설정 허용**을 누르세요. 게임으로 돌아와 **접근성 설정 열기**에서 터치 기록을 켭니다. [Android 공식 도움말](https://support.google.com/android/answer/12623953?hl=ko)
- 목적지를 고르면 **터치 1,000회당 지도 한 칸** 이동합니다. 목적지를 정하기 전이나 도착 후에 쌓인 터치는 1,000회마다 이동 자원 1개가 되고 나머지도 보관됩니다. 접근성 서비스를 끄면 12시간마다 받는 이동 자원을 직접 사용할 수 있습니다.
- 홈의 **남은 행동**은 폰 사용 시간으로 쌓인 행동과 이동 자원으로 받은 행동의 합계입니다. **행동 20회 받기**를 누르면 이동 자원 1개가 행동 20회로 바뀝니다. 모험하는 중에도 폰 사용 시간 20초마다 행동이 1회 쌓입니다.
- 알림에서 오늘 터치 횟수를 확인할 수 있습니다. 펼친 알림에는 월간 터치·오늘 폰 사용 시간과 **1번 슬롯 동료의 도트·레벨·경험치**가 표시됩니다.
- 진행과 통계는 기기에 저장합니다. 업데이트할 때 기존 앱 위에 덮어 설치하면 진행을 이어갈 수 있습니다.
- **설정 → 앱 업데이트 설치 허용**은 처음 한 번 설정합니다. 이후 새 버전을 자동 확인·다운로드하고, 다운로드가 끝나면 배틀·연출 종료를 기다리지 않고 현재 상태를 저장한 뒤 바로 설치합니다. 기기에서 추가 승인을 요구하면 설정에 시스템 설치 화면 버튼이 표시됩니다.
- **지금 확인**은 캐시된 응답을 재사용하지 않고 새 배포 정보를 요청합니다. 화면에 표시하는 앱 버전은 실제 설치된 APK 기준입니다. 확인 실패를 최신 버전으로 표시하지 않으며, 앱을 켜 둔 동안에도 주기적으로 확인합니다. v0.1.1에서 최신으로 잘못 표시된다면 먼저 이 APK로 한 번 덮어 설치하세요.
- Android 채널은 Windows의 `latest` 릴리스와 분리되어 있습니다. Android 16 에뮬레이터에서 실제 GitHub 업데이트 확인·다운로드·자체 설치와 저장 보존을 확인했습니다. 접근성 설정 화면은 기기마다 조금씩 다를 수 있습니다.

모바일 도감은 한 줄에 4마리씩 표시하며, 포켓몬을 선택하면 상세 화면으로 이동합니다. 상단의 **도감 목록** 또는 Android 뒤로 가기로 목록에 돌아옵니다. 타운맵은 **지도·배지함**으로 구성됩니다. 장소를 눌러 살펴본 뒤 **이곳으로 이동**을 누르세요. 저장한 자원은 **이동 자원 사용**을 눌렀을 때 사용합니다. 마을에서도 인접한 도로의 포켓몬을 만나며, 체육관의 관장과 라인업은 지도 아래에서 확인할 수 있습니다. 새로운 소식은 `!`로 표시됩니다. 지나온 모험과 나눈 이야기는 **모험 기록**에서 확인하세요.

이야기 속 대화와 보상, 도전, 길목 통과는 자동으로 이어집니다. 선택지가 나오면 직접 골라 주세요.

도전할 때는 진행 중인 동작을 마친 뒤 야생 배틀을 보관합니다. 도전이 끝나면 다음 폰 사용으로 같은 야생 상대와 이어서 모험합니다.

타운맵의 **라이벌 매치** 블록에서 재도전이 필요한 상대의 라인업과 버튼을 확인할 수 있습니다. 승부를 마치면 대기 상태로 돌아갑니다.

설정의 **완전 초기화**에서 확인 후 도감과 모든 게임 진행을 지우고 다시 시작할 수 있습니다. 터치 횟수와 폰 사용 시간 통계는 유지합니다. 이동 잔액과 모험 진행은 처음부터 시작합니다.

월간 시즌과 누적 도감은 기존 게임 규칙을 유지합니다. 새로운 만남과 진행 요소는 모험 속에서 직접 발견해 보세요.

모험 기록의 요약은 이번 시즌 전체 결과를 보여 줍니다. 별도의 확인 버튼 없이 누적되며 상세 기록도 유지됩니다.

원작과 라이선스 표기는 앱의 **설정**에서 확인할 수 있습니다.

## 개발과 검증

필요 환경: Node.js **22.11.0**, JDK **17 이상** (현재 Android Studio JBR 사용), Android SDK **36**, Build Tools **36.1.0**. Gradle **8.13**의 wrapper와 배포 SHA-256, Android Gradle Plugin **8.13.0**, npm 잠금 파일을 소스에 고정합니다.

```powershell
npm.cmd ci
npm.cmd run mobile:build
npm.cmd run mobile:test
# APK 빌드와 Android lint 포함
powershell -NoProfile -ExecutionPolicy Bypass -File mobile/scripts/verify-android.ps1 -WithBuild
```

첫 release 빌드는 `%LOCALAPPDATA%/PokemonIdleSigning/pokemon-idle-release.jks`와 Git에서 제외된 `mobile/android/keystore.properties`를 생성합니다. **둘 다 안전하게 보관하세요.** 키를 잃으면 같은 앱을 업데이트할 수 없습니다. 다른 PC에서는 기존 키와 설정을 복원해야 합니다. 키·비밀번호를 Git이나 릴리스에 올리지 마세요. 디버그 APK는 `build-android.ps1 -DebugBuild`로 별도 앱 ID를 사용합니다.

결과는 `mobile/android/app/build/outputs/apk/release/app-release.apk`입니다. 검증된 배포본은 `dist/android/<version>/`에 APK·체크섬·릴리스 식별 정보를 함께 보관합니다. Windows 배포본과 사용자 데이터는 건드리지 않습니다.

`build-web.cjs`는 잠긴 의존성과 기존 게임 코드를 브라우저용 CommonJS 묶음으로 만듭니다. 전투 엔진을 새로 작성하지 않으며 Node.js/Electron 실행 환경이나 SSH 기능은 APK에 포함하지 않습니다. Android WebView는 앱 안의 고정 HTTPS 출처에서 패키지 리소스만 열며 외부 페이지·파일 접근을 차단합니다.

`build-notification.cjs`는 같은 도트와 성장표로 네이티브 알림 리소스를 생성하며 Gradle `preBuild`에서 자동 실행됩니다. 펼친 알림만 RemoteViews를 사용하고, 도트는 Android의 AnimatedImageDrawable로 재생합니다. 저장 성공 후 표시할 정보가 바뀔 때 알림을 갱신하며, 알림 표시가 게임 행동을 발생시키지는 않습니다. 격리 에뮬레이터의 `mode=notification-partner` 검사는 실제 SystemUI에서 도트 프레임 변화와 슬롯·레벨·경험치 갱신을 확인합니다.

터치 횟수와 폰 사용 시간은 기기에 집계합니다. 게임이 반영한 터치·사용 시간과 모험 진행은 한 AtomicFile로 함께 저장합니다. AndroidX JavaScriptEngine **1.1.1**의 별도 실행 환경에서 동일한 게임 묶음을 사용해, 다른 앱을 쓰는 동안에도 모험을 이어갑니다. 게임 화면으로 돌아오면 최신 저장을 다시 불러옵니다. 의존성 버전은 `mobile/android/app/gradle.lockfile`에 고정합니다.

계측 검사는 별도 `androidTest` APK의 `MobileTest`로 실행합니다. 게임 화면·도감·가방·뱃지·실제 Activity 백그라운드 정지·터치 횟수의 단일 반영·저장 거부·업데이트 무결성 거부를 확인합니다. `mode=update`는 같은 서명의 상위 APK가 든 test asset으로 설치 세션을 제출하며, 제출 성공은 설치 완료를 뜻하지 않습니다. 외부에서 실제 설치 버전 코드를 확인한 뒤 `mode=preserved`로 진행 보존을 확인해야 합니다. 에뮬레이터 계측의 범위는 테스트 기기와 검증한 이벤트에 한정됩니다.

업데이트 확인 회귀 검사는 `mode=update-checks`로 HTTP 오류·잘못된 정보·재시도·수동 확인·캐시 우회를 확인합니다. 상위 공개 버전보다 낮은 버전 코드로 만든 격리 기기에서 `mode=update-live`는 설정의 **지금 확인** 버튼을 눌러 실제 GitHub APK와 표시 버전을 확인하며, `-e install true`로 설치도 제출합니다. 실제 설치 코드 확인과 `mode=update-preserved`의 저장 파일 해시 비교가 통과해야 업데이트 완료로 기록합니다.

업데이트 정보는 `mobile/updates/android.json`에서 읽습니다. APK 크기·SHA-256·앱 ID·상위 버전 코드·현재 설치된 서명과의 일치를 검증한 후 Android PackageInstaller로 자기 자신을 교체합니다. 공개된 APK는 바꾸지 않고 새 버전 코드를 발급합니다. Android 릴리스에는 `--latest=false`를 지정하여 Windows 업데이트 채널을 유지하세요.
