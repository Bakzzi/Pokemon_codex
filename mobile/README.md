# 포켓몬 작은 모험 · Android

화면을 켜 두면 동료들이 자동으로 모험하고, 앱을 꺼 둔 동안에는 걸은 만큼 모험하는 비공식 비영리 팬 게임입니다. 원작 **모모찡 · momozzing**의 [Digimon_mod](https://github.com/momozzing/Digimon_mod)에서 출발했습니다. 기존 Windows 앱과 별개로 저장됩니다.

## 설치와 사용

Android 12 이상에서 [Android 배포본](https://github.com/Bakzzi/Pokemon_codex/releases/tag/android-v0.1.11)의 APK를 설치하세요. 첫 실행에는 안내 대사를 터치해서 넘기며 모험을 시작합니다. **포켓기어 · 도전하기 · 가방보기 · 모험 기록**에서 동료와 진행을 확인하세요.

- 게임 화면이 열려 있으면 기존 배틀 연출 속도로 자동 모험합니다. 다른 앱으로 전환하거나 화면을 꺼도 기록한 **10걸음당 모험 행동 1회**를 백그라운드에서 진행합니다. 다시 열면 진행된 결과를 확인할 수 있습니다.
- **설정 → 걸음 기록** 토글을 켜고 신체 활동 권한을 허용하세요. 걸음 기록 알림을 유지하는 서비스가 사용됩니다. 꺼 둔 동안 **10걸음마다 모험 행동 1회**를 처리하고 진행과 사용한 걸음을 함께 저장합니다. 이미 반영한 걸음은 다시 지급하지 않습니다.
- **모험의 발걸음**에는 오늘과 누적 걸음 수가 표시되고, 알림에서도 오늘 걸음을 확인할 수 있습니다. 기기 시간의 자정에 오늘 걸음만 초기화되며 누적 걸음과 아직 쓰지 않은 모험 보상은 유지됩니다. 앱을 켜고 걸은 수도 만보기에 기록하지만 모험 보상을 중복 지급하지 않습니다.
- 걸음 센서가 없거나 권한이 없으면 켜 둔 모험만 사용할 수 있습니다. 백그라운드 계산을 지원하지 않는 오래된 Android System WebView에서는 걸음을 보존했다가 앱을 열 때 처리합니다. 강제 종료, 권한 해제, 제조사 절전 제한으로 기록되지 않은 걸음은 추정하지 않습니다. 걷지 않은 대기 시간에는 보상이 없습니다.
- 다른 앱 사용 시간이나 AI 토큰을 읽지 않습니다. 걸음 기록과 진행은 기기 안에 저장합니다. 앱 삭제 시 로컬 진행도 삭제되므로 업데이트할 때 앱을 먼저 지우지 마세요.
- **설정 → 앱 업데이트 설치 허용**은 처음 한 번 설정합니다. 이후 새 버전을 자동 확인·다운로드하고, 다운로드가 끝나면 배틀·연출 종료를 기다리지 않고 현재 상태를 저장한 뒤 바로 설치합니다. 기기에서 추가 승인을 요구하면 설정에 시스템 설치 화면 버튼이 표시됩니다.
- **지금 확인**은 캐시된 응답을 재사용하지 않고 새 배포 정보를 요청합니다. 화면에 표시하는 앱 버전은 실제 설치된 APK 기준입니다. 확인 실패를 최신 버전으로 표시하지 않으며, 앱을 켜 둔 동안에도 주기적으로 확인합니다. v0.1.1에서 최신으로 잘못 표시된다면 먼저 이 APK로 한 번 덮어 설치하세요.
- Android 채널은 Windows의 `latest` 릴리스와 분리되어 있습니다. Android 16 에뮬레이터에서 실제 GitHub 업데이트 확인·다운로드·자체 설치와 저장 보존을 확인했습니다. 실제 걸음 기록과 기기별 설치 동작은 실기기 확인이 필요합니다.

모바일 도감은 한 줄에 4마리씩 표시하며, 포켓몬을 선택하면 상세 화면으로 이동합니다. 상단의 **도감 목록** 또는 Android 뒤로 가기로 목록에 돌아옵니다. 도전하기의 카드는 접힌 상태로 시작하며 제목을 눌러 펼칠 수 있습니다.

트레이너와 대화할 때는 화면 아래 대사 상자를 터치하세요. 대화 중에는 배틀과 걸음 사용이 멈추며, 앱을 다시 열어도 같은 대사부터 이어집니다.

설정의 **완전 초기화**에서 확인 후 도감과 모든 게임 진행을 지우고 다시 시작할 수 있습니다. 만보기 기록과 설정은 유지하며 쌓아 둔 모험 행동은 새 게임에 반영하지 않습니다.

월간 시즌과 누적 도감은 기존 게임 규칙을 유지합니다. 새로운 만남과 진행 요소는 모험 속에서 직접 발견해 보세요.

모험 기록의 요약은 이번 시즌 전체 결과를 보여 줍니다. 별도의 확인 버튼 없이 누적되며 상세 기록도 유지됩니다.

원작과 라이선스 표기는 앱의 **설정**에서 확인할 수 있습니다. 업데이트 전 이미 기록된 걸음은 누적 걸음에 보존하며, 과거에 기록하지 않은 걸음은 소급 계산하지 않습니다.

## 개발과 검증

필요 환경: Node.js **22.11.0**, JDK **17 이상** (현재 Android Studio JBR 사용), Android SDK **36**, Build Tools **36.1.0**. Gradle **8.13**의 wrapper와 배포 SHA-256, Android Gradle Plugin **8.13.0**, npm 잠금 파일을 소스에 고정합니다.

```powershell
npm.cmd ci
npm.cmd run mobile:build
npm.cmd run mobile:test
# APK 빌드와 Android lint 포함
powershell -NoProfile -ExecutionPolicy Bypass -File mobile/scripts/verify-android.ps1 -WithBuild
```

첫 release 빌드는 `%LOCALAPPDATA%/PokemonIdleSigning/pokemon-idle-release.jks`와 Git에서 제외된 `mobile/android/keystore.properties`를 생성합니다. **둘 다 안전하게 보관하세요.** 키를 잃으면 같은 앱을 업데이트할 수 없습니다. 다른 PC에서는 기존 키와 설정을 복원해야 합니다. 키·비밀번호를 Git이나 릴리스에 올리지 마세요. 디버그 APK는 `build-android.ps1 -DebugBuild`로 별도 앱 ID를 사용합니다.

결과는 `mobile/android/app/build/outputs/apk/release/app-release.apk`입니다. 검증된 배포본은 `dist/android/<version>/`에 APK·체크섬·릴리스 식별 정보를 함께 보관합니다. Windows 배포본과 사용자 데이터는 건드리지 않습니다.

`build-web.cjs`는 잠긴 의존성과 기존 게임 코드를 브라우저용 CommonJS 묶음으로 만듭니다. 전투 엔진을 새로 작성하지 않으며 Node.js/Electron 실행 환경이나 SSH 기능은 APK에 포함하지 않습니다. Android WebView는 앱 안의 고정 HTTPS 출처에서 패키지 리소스만 열며 외부 페이지·파일 접근을 차단합니다.

걸음 센서의 누적 값, 부팅 식별자, 화면 상태를 로컬 장부로 관리합니다. 화면 전환을 가로질러 뒤늦게 들어온 모호한 표본은 보수적으로 제외합니다. 반영한 걸음의 커서와 게임 진행은 한 AtomicFile로 함께 저장합니다. AndroidX JavaScriptEngine **1.1.1**의 별도 실행 환경에서 동일한 게임 묶음을 사용하며, 화면용 WebView나 Activity 없이 걸음 행동을 처리합니다. UI가 돌아오면 저장 권한을 회수하고 최신 진행을 다시 불러옵니다. 오래된 계산 결과와 지연된 UI 저장은 최신 진행을 덮어쓸 수 없습니다. 의존성 버전은 `mobile/android/app/gradle.lockfile`에 고정합니다. 센서 장부는 재부팅 시 기준만 새로 잡고 누적 보상 수는 유지합니다.

계측 검사는 별도 `androidTest` APK의 `MobileTest`로 실행합니다. 게임 화면·도감·가방·뱃지·실제 Activity 백그라운드 정지·걸음 fixture의 단일 반영·저장 거부·업데이트 무결성 거부를 확인합니다. `mode=update`는 같은 서명의 상위 APK가 든 test asset으로 설치 세션을 제출하며, 제출 성공은 설치 완료를 뜻하지 않습니다. 외부에서 실제 설치 버전 코드를 확인한 뒤 `mode=preserved`로 진행 보존을 확인해야 합니다. 센서 fixture 통과는 실기기 보행 검증을 뜻하지 않습니다.

업데이트 확인 회귀 검사는 `mode=update-checks`로 HTTP 오류·잘못된 정보·재시도·수동 확인·캐시 우회를 확인합니다. 상위 공개 버전보다 낮은 버전 코드로 만든 격리 기기에서 `mode=update-live`는 설정의 **지금 확인** 버튼을 눌러 실제 GitHub APK와 표시 버전을 확인하며, `-e install true`로 설치도 제출합니다. 실제 설치 코드 확인과 `mode=update-preserved`의 저장 파일 해시 비교가 통과해야 업데이트 완료로 기록합니다.

업데이트 정보는 `mobile/updates/android.json`에서 읽습니다. APK 크기·SHA-256·앱 ID·상위 버전 코드·현재 설치된 서명과의 일치를 검증한 후 Android PackageInstaller로 자기 자신을 교체합니다. 공개된 APK는 바꾸지 않고 새 버전 코드를 발급합니다. Android 릴리스에는 `--latest=false`를 지정하여 Windows 업데이트 채널을 유지하세요.
