# 안드로이드 모바일 앱 요구사항

개발 브랜치는 `mobile`이며 Windows v0.3.83을 출발점으로 한다.

## 확정 범위

- 안드로이드 앱만 개발한다. 아이폰 지원은 범위에서 제외한다.
- 기존 배틀·포획·육성·도감 기능을 모바일에서 사용할 수 있게 한다.
- 이 게임을 켜 둔 동안에는 방치형 RPG처럼 자동으로 모험한다. 게임을 꺼 둔 동안에는 걸음 수로만 모험을 진행한다. 토큰 사용량이나 다른 앱 사용 시간은 진행 조건이 아니다.
- 자동 업데이트를 필수 기능으로 포함한다. 안드로이드는 자동 확인·다운로드·설치까지 기본 흐름으로 삼으며, 매번 설치 확인 버튼을 누르는 방식을 기본안으로 잡지 않는다.
- 앱 아이콘은 2·3세대 느낌의 도트 몬스터볼로 한다. 기존 게임에 쓰인 도트를 사용하며, 리소스와 미리보기는 `mobile/assets/icon`에 둔다.

## 업데이트 요구사항

- 새 버전 확인, 내려받기, 적용까지 사용 중인 배포 경로에 맞게 연결한다.
- 앱 본체 업데이트와 문구·게임 데이터 등의 갱신을 구분한다. 자동 반영 범위는 선택한 기술과 플랫폼 규칙에 맞춰 정한다.
- 포켓몬, 누적 도감, 진행 기록과 설정을 보존한다. 업데이트가 준비되면 배틀 종료를 기다리지 않고 현재 상태를 저장한 뒤 바로 적용한다.
- 내려받기나 적용이 실패해도 기존 정상 버전과 저장된 진행을 보존한다.
- 운영체제가 요구하는 설치 권한과 승인 상태를 존중한다. 모든 안드로이드 버전과 기기에서 무조건 무인 설치가 된다고 가정하지 않는다.
- 안드로이드는 GitHub의 APK를 앱이 받아 자기 자신을 업데이트하는 경로를 기준으로 설계한다. 스토어 등록을 전제로 하지 않는다.

## 잠금 시간과 걸음 수 모험

| 게임 상태 | 진행 방식 |
| --- | --- |
| 폰 잠금 | 관측한 10초마다 모험 행동 1회 |
| 잠금 중 걷기 | 기록한 10걸음마다 추가 행동 1회 |
| 폰 사용 중 | 일반 모험 정지, 도전 배틀은 앱에서 진행 |

- 잠금은 화면 꺼짐과 키가드 상태로 판정하며 앱의 전경·배경 여부와 구분한다. 다른 앱 사용 시간은 보상하지 않는다.
- 시간은 재부팅 식별자와 단조 시계로 집계한다. 서비스 중단 구간은 추정하지 않는다. 절전으로 실행이 지연되면 관측이 이어진 잠금 구간을 반영한다.
- 잠금 시간과 걸음의 사용 커서를 게임과 같은 원자적 파일에 저장한다. 각 활동의 나머지를 보존하며 재시작·업데이트에 중복 지급하지 않는다.
- 걸음 권한이나 센서가 없어도 잠금 모험을 지원한다. 만보기는 전체 걸음, 모험 보상은 잠금 중 걸음만 집계한다. 사용 통계 접근 권한은 요구하지 않는다.
- 도전 요청 시 실행 중인 공격·포획 연출과 확정된 결과를 마친다. 남은 야생 배틀의 상대·체력·PP·상태·턴을 보관하고 도전한다. 도전 후 다음 잠금부터 야생 배틀을 재개한다.
- 대화는 사용자 입력으로만 넘긴다. 도전 배틀은 앱 전경에서 진행하며 잠금 활동 잔액을 소모하지 않는다. 사파리 걸음은 시간으로 대체하지 않는다.

## 걸음 표시와 모바일 화면

- 메인 화면의 걸음 카드 이름은 **모험의 발걸음**으로 한다. 오늘 걸음과 앱과 함께 걸은 누적 걸음을 표시한다.
- 지속 알림에는 오늘 걸음을 표시한다. 기기 시간의 매일 자정에 오늘 걸음만 초기화하고 누적 걸음·남은 모험 보상·진행은 보존한다.
- 만보기는 기록 중인 모든 걸음을 집계한다. 앱을 켜고 걸은 수를 꺼 둔 모험 보상으로도 지급하지 않는다.
- 원작 표기는 설정에서 유지하며 메인·포켓기어·도전하기·가방·모험 기록에는 표시하지 않는다. 라이선스 파일과 문서의 출처는 보존한다.
- 앱 재실행 때 꺼 둔 시간을 다음 행동 대기시간에 중복해서 더하지 않는다. 진행 중이던 연출의 남은 대기시간만 유지한다.
- 모험 기록은 확인 버튼 없이 이번 시즌 결과를 누적한다. 상세 기록은 기존 보관 범위를 유지한다.

## 안드로이드 자동 설치

- Android 12(API 31) 이상의 공식 자가 업데이트 기능을 사용한다. 첫 설치와 이 앱의 설치 권한 허용은 사용자 설정 과정으로 구분한다.
- `REQUEST_INSTALL_PACKAGES`와 `UPDATE_PACKAGES_WITHOUT_USER_ACTION`을 선언하고, 설치 세션에 `setRequireUserAction(USER_ACTION_NOT_REQUIRED)`를 지정한다.
- 실행 중인 앱 자신을 대상으로 업데이트한다. 운영체제별 대상 API 요구 수준, 앱 식별자, 더 높은 버전 코드와 서명 호환성을 확인한다.
- 내려받은 APK의 무결성을 확인하고 저장을 마친 안전한 시점에 자동 설치한다. 진행 파일을 삭제하거나 앱을 제거한 뒤 설치하는 방식을 사용하지 않는다.
- 운영체제가 `STATUS_PENDING_USER_ACTION`을 반환하면 설치 완료로 처리하지 않는다. 추가 승인이 필요한 예외 상태로 표시하고, 강제 클릭이나 반복 설치로 우회하지 않는다.
- Android 12 미만이나 제조사별 추가 제한이 있는 기기에 동일한 무인 설치를 보장하지 않는다. 지원 범위는 실제 APK 업데이트 검증 뒤 명시한다.
- Android 에뮬레이터 검증과 실기기 검증을 구분하여 배포 기록에 남긴다.

## 확인한 플랫폼 문서

- [Android 걸음 센서](https://developer.android.com/develop/sensors-and-location/sensors/sensors_motion#sensors-motion-stepcounter): 누적 걸음 값과 활동 인식 권한을 제공하며 재부팅 등 센서 조건을 고려해야 한다.
- [Health Connect 걸음 집계](https://developer.android.com/health-and-fitness/health-connect/aggregate-data): 지원 기기에서 여러 출처의 중복을 처리한 걸음 수를 읽을 수 있다. 백그라운드 읽기는 별도 권한과 기능 지원을 확인한다.
- [Android 인앱 업데이트](https://developer.android.com/guide/playcore/in-app-updates): Google Play의 업데이트 흐름이며 사용자 승인 과정이 있다.
- [Android 설치 세션의 사용자 동작 요구](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int)): Android 12 이상에서 조건을 충족한 자가 업데이트는 사용자 동작 없이 진행할 수 있다. 설치 세션의 승인 대기 결과도 처리해야 한다.
- [사용자 동작 없는 업데이트 권한](https://developer.android.com/reference/android/Manifest.permission#UPDATE_PACKAGES_WITHOUT_USER_ACTION): API 31부터 제공하는 일반 권한이다.

구현·설치·개발 방법과 검증 범위는 [모바일 안내](../../mobile/README.md) 및 Android 릴리스 기록에서 확인한다.
